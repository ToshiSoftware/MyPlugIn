# MyMaximizer 設計書

マスタートラックの最後に挿すマキシマイザー（ブリックウォール・リミッタ＋アップワード・コンプ）。
Sources: `Sources/MyMaximizer`、tests: `Tests/MyMaximizerTests`。

| 項目 | 値 |
|---|---|
| 名前 | MyMaximizer（MyDAW では "MyDAW: MyMaximizer"） |
| Subtype | `MMax`（一度決めたら変更不可） |
| 型名プレフィックス | `Maximizer...`（MyDAW は全ソースを 1 モジュールでコンパイルするため） |
| 信号経路 | IN → INPUT GAIN → UPWARD COMPRESS（AGC）→ 先読みリミッタ（THRESHOLD から Soft Knee、天井 = OUTPUT LEVEL）→ 安全クリップ → OUT |
| レイテンシ | 先読み 10 ms 固定（48 kHz で 480 サンプル、ATTACK の最大値）。AU の `latency` で報告する（§3.5） |
| テール | 0（ただし先読み分の 10 ms は出力が遅れて出る） |
| エディタ | 300 × 460 px（`MyFXAudioUnit.editorSize` で指定） |
| 負荷 | UPWARD 0 dB は計算しない。INPUT GAIN 0 dB は乗算しない。リミッタは常に動く（本体なので） |

### 改訂履歴

- ドラフト 1: 初版（2026-10-09）。
- ドラフト 2: UPWARD の THRESHOLD をパラメータ化（dBFS、初期値 −12 dB）。リミッタのリリースを
  RELEASE（SLOW ⇄ FAST、中央が推奨）で可変に。トゥルーピークは入れないことに確定。
  MyDAW はトラックのインサートの遅延も補正していることを確認。
- 実装 1: 本書どおり実装（2026-10-09）。補足:
  - リミッタの目標ゲインは天井の 0.0001 dB 下を狙う（平均計算の丸めで天井を超えないため）。安全クリップは全テストで 0 回。
  - 長い圧縮の後の遅いリリースは、ゲインが戻り切る（−0.01 dB）まで遅いまま保つ。
  - RELEASE の数値入力は速い段の ms（例: `40` → 中央、`160` → SLOW 端）。
  - THRESH / UPWARD のフェーダ見出しの色のため、`MyFXFaderColumn` に `nameColor`（既定は従来色）を追加。
  - バイパス中もチェーンは動かし続け、遅延させた入力へ 10 ms でクロスフェードする（戻すときにもクリックなし）。
  - 履歴はエディタを開いた時点の分もすぐ表示する。
- 実装 2（2026-10-09）: ユーザー指示で変更。本書の §1〜§3 は実装 2 の内容に更新済み。
  - リミッタの ATTACK（0〜10 ms、初期値 0）と RELEASE（10〜500 ms、初期値 50 ms）を個別のパラメータにし、
    縦フェーダに移した。RELEASE の横フェーダ行は削除（エディタ 300 × 460）。リリースは 1 段に。
  - 先読み（レイテンシ）は ATTACK の最大値 10 ms で固定。ATTACK は先読みの中でゲインを下げ始める位置だけを変える。
  - UPWARD: アタック = リミッタの ATTACK、リリース = リミッタの RELEASE × 10、しきい値 −12 dBFS 固定
    （THRESH パラメータ `upward_threshold` は削除。アドレス 11 は空き）。
  - 不具合修正: 入力が無音になると UPWARD のブーストが 0 dB に戻っていた（無音ゲートでブーストを 0 へ下げていた）。
    −60 dBFS 未満ではブーストをその値のまま保持するように変更。曲が戻ったとき、持ち上げた状態から続く。
- 実装 3（2026-10-09）: 「−12 dB 固定」は UPWARD のみ。メインリミッタに THRESHOLD（`threshold`、アドレス 22、
  −30〜0 dB、初期値 0 dB）を追加。マキシマイザー型（Waves L2 / Ozone と同じ）: THRESHOLD を下げた分だけ信号を
  持ち上げてリミッタに送り、THRESHOLD を超えた部分を削ってピークを OUTPUT に揃える。フェーダは 6 本。
- 実装 4（2026-10-09）: THRESHOLD を再設計。INPUT（送り込む量）と重複しないよう、THRESHOLD は「圧縮が始まる位置」に。
  THRESHOLD を超えたピークを Soft Knee の曲線で OUTPUT に向かって滑らかに圧縮する（OUTPUT は超えない）。
  初期値は −0.1 dB（OUTPUT と同じ＝従来のブリックウォール）。THRESHOLD が OUTPUT より上なら OUTPUT として扱う。
  グラフに THRESHOLD の赤い点線（OUTPUT より下のときだけ）を追加。使い方は §0 にまとめた（マニュアルの元）。
- 実装 5（2026-10-09）: UPWARD のしきい値の緑の点線を削除。スクロール時のちらつきを修正:
  - 原因 1: 6 s / 12 s 表示で列をまとめる組を最新の列から数えていたため、更新ごとに届く列数が奇数だと
    全部の組がずれ、グラフ全体の値が毎回変わっていた → 組を列の通し番号で固定し、そろった組だけ表示。
  - 原因 2: 1 点の幅が約 0.96 pt で、列ごとの長方形の端の滲みがスクロールのたびに変わっていた
    → グラフ幅を 284 pt（1 点 = 1 pt）にし、各層を 1 枚の輪郭で描いて縦の辺をデバイスピクセルに揃えた。
  - 1 点ぶん進むと、前の絵をちょうど 1 点左へずらした絵になることをピクセル比較のテストで確認。

## 0. 使い方（マニュアルの元）

MyMaximizer は音圧を上げるためのマキシマイザー。マスタートラックの最後に挿す。

| つまみ | 役割 |
|---|---|
| INPUT | リミッタに送り込む量。上げるほど音圧が上がる（上げすぎると歪む・平坦になる） |
| UPWARD | 小さい部分（−12 dBFS より小さいところ）を最大この量まで持ち上げる。曲の静かな部分の密度を上げる |
| THRESH | 圧縮が始まる位置。ここを超えたピークを OUTPUT に向かって柔らかく（Soft Knee）潰す |
| ATTACK | ピークに対してゲインを下げ始める早さ。0 ms＝ピークで即座（最も大きくなるが歪みやすい）、長くすると柔らかい |
| RELEASE | ゲインが戻る速さ。短いほど音圧が上がるが、うねり・歪みが出やすい。UPWARD の戻りはこの 10 倍 |
| OUTPUT | 天井。出力はこの値を超えない（配信用なら −0.1〜−1 dB） |

基本の手順:

1. 挿した直後は THRESH = OUTPUT（−0.1 dB）で、普通のブリックウォール・リミッタとして動く。
2. INPUT を上げて音圧を決める。グラフの赤（GR）が常に数 dB を超えるようなら上げすぎ。
3. ピークの潰れ方が硬い（パツパツする）と感じたら THRESH を下げる。THRESH から上がなだらかに圧縮され、
   OUTPUT の手前でゆっくり頭打ちになる。−3〜−6 dB 程度が目安。
4. 静かな部分を持ち上げたいときは UPWARD を上げる（初期値 +2 dB）。
5. ATTACK / RELEASE は初期値（0 ms / 50 ms）から、歪みやうねりが気になったときだけ長くする。

THRESH の効き方の例（OUTPUT −0.1 dB、THRESH −6 dB）:

| 入力ピーク | 出力ピーク |
|---|---|
| −6 dB 以下 | 変わらない |
| −3 dB | −3.7 dB |
| 0 dB | −2.2 dB |
| +6 dB | −0.9 dB |
| +12 dB | −0.4 dB |

IN / OUT メータの CLIP ランプは 0 dBFS 以上のサンプルで点灯し、クリックするまで消えない。
OUT の CLIP は通常点かない（点いたら不具合）。

### 1.2 IN / OUT メータ（横向き、CLIP 表示付き）

- 既存の `MyFXMeterRow`（L/R 2 本、−96〜+6 dB の MyDAW テーパ、1.5 s ピークホールド、
  最大値の読み値はクリックでクリア）に **CLIP ランプ** を足す（Core の変更、§4.1）。
- ランプはバーと読み値の間、8 × 11 px。L/R どちらかのサンプルが **|x| ≥ 1.0（0 dBFS 以上）** になったら赤く点灯し、
  **クリックするまで消えない**（ラッチ）。読み値をクリックしても一緒に消える。
- IN はプラグインに入ってきた信号（INPUT GAIN の前）。OUT は最終出力。
  OUT は天井（既定 −0.1 dB）で抑えているので、正しく動いていれば OUT の CLIP は点かない（動作確認の目安になる）。
- 検出はサンプルピーク。サンプル間ピーク（トゥルーピーク）は見ない（不要と確定）。

### 1.4 ヒストリ・グラフ（右から左へ流れる）

Ozone Maximizer の波形表示のイメージ。最新が右端、時間とともに左へ流れる。

- 大きさ 284 × 120 pt（ストリップの内幅いっぱい、1 点 = 1 pt）。表示時間 6 s（1 点 ≈ 21 ms）。
  グラフをクリックすると 3 s → 6 s → 12 s と切り替わる（表示だけの設定。保存しない）。
- 縦軸は 1 本の dB 目盛で統一: 上端 0 dBFS、下端 −30 dBFS（**4 px/dB**）。
  グリッド −6 / −12 / −18 / −24 dB（細い線）、OUTPUT（天井）の位置に白の点線、
  THRESH が OUTPUT より下のときは THRESH の位置に赤の点線（圧縮がどこから始まるかが見える）。
- 3 つの量を同じ目盛で重ねる（目盛が 1 つなので「何 dB か」が見た目でそのまま読める）:

| 量 | 描き方 | 色 | 1 列の値 |
|---|---|---|---|
| レベル | 下端から上へ塗りつぶし＋上端に明るい線 | 青緑（Ozone 風） | 出力のピーク（列の中の最大） |
| リミッタ量（GR） | **上端から下へ** 垂れ下がる塗りつぶし（半透明） | 赤 | 列の中の最大 GR（dB） |
| UPWARD 量 | **下端から上へ** 伸びる塗り＋明るい緑の縁取り（ブーストがある所だけ） | 緑 | 列の中の平均ブースト（dB） |

  例: GR 3 dB → 上端から 12 px の赤、UPWARD +2 dB → 下端から 8 px の緑。
  出力は天井に張り付くので、GR の赤はレベルの上端に重なり「頭を削った」ように見える（Ozone と同じ見え方）。
- 下の読み値の行（14 px）: `GR −2.3 dB`（現在値、赤）、`UP +1.4 dB`（現在値、緑）、右端に表示時間 `6 s`。
  30 Hz の更新ごとの最大 GR／平均ブーストを **ピークホールド** して表示（読めるように）:
  大きい値が来たら即座に更新し、1 s 保持、その後は時定数 0.2 s で現在値へ戻る。
- エディタを開いた瞬間に過去の 6 s も見えるよう、履歴はカーネル側で常に記録しておく（§3.6）。
- バイパス中は列を「無効」として記録し、グレーで描く（効いていない時間が分かる）。

## 2. パラメータ

アドレス（＝`rawValue`）と identifier はプロジェクトに保存されるので、確定後は変更不可。
将来の追加（キャラクタ、トゥルーピーク等）のためアドレスに隙間を空ける。

| アドレス | identifier | 範囲 | 単位 | 初期値 |
|---|---|---|---|---|
| 0 | `input_gain` | −12〜+24 | Decibels | 0.0 |
| 10 | `upward` | 0〜+12 | Decibels | +2.0 |
| 22 | `threshold` | −30〜0 | Decibels | −0.1 |
| 31 | `attack` | 0〜10 | Milliseconds | 0.0 |
| 30 | `release` | 10〜500 | Milliseconds | 50 |
| 20 | `output_level` | −12〜0 | Decibels | −0.1 |

計 6 パラメータ（ホストでの並びは上の表の順＝フェーダの順）。`MyFXParameter` の 1 enum（`MaximizerParameter`）にまとめる。
アドレス 11（旧 THRESH）と 21（トゥルーピーク用）は使わない。
dB のパラメータは 20 ms の 1 極スムージングで追う（ジッパーノイズ防止）。
ATTACK / RELEASE は時定数を変えるだけなのでスムージング不要（ブロックごとに反映）。

## 3. 信号処理

ステレオリンク（L/R に同じゲイン）。モノラル（1 ch）でも同じ処理。
内部状態・エンベロープは Double、オーディオは Float。

### 3.1 INPUT GAIN

dB → リニア、スムージング後に乗算。0.0 dB（スムージング後も）なら乗算しない。

### 3.2 UPWARD COMPRESS（AGC）

小さい部分を持ち上げる「上向き」のコンプ。最大 +UPWARD dB まで持ち上げ、大きい部分では 0 dB に戻る。

1. 検出: `e = max(|L|, |R|)` を dB に。ピーク型エンベロープ（立ち上がり即時、下がり 50 ms）。
2. 目標ブースト: `b = clamp(T − e, 0, A)`
   - A = UPWARD（dB）、T = −12 dBFS（固定）。
   - しきい値に近い／超える部分（大きい部分）はブースト 0、それより小さい部分ほどブースト、上限 A。
3. 無音ではブーストを保持: `e` が −60 dBFS 未満の間はブーストをその値のまま止める
   （0 dB に戻さない。曲間やブレイクの後、持ち上げた状態から続く。ノイズを今以上には上げない）。
   ただし UPWARD を下げた場合は無音中でもその値まで下げる。
4. 平滑（dB 領域の分岐型 1 極）:
   - **アタック（ブーストを下げる方向）= リミッタの ATTACK**（0 ms なら即座）
   - **リリース（ブーストを上げる方向）= リミッタの RELEASE × 10**（初期値で 500 ms）
   - アタックで取り切れない一瞬のオーバーシュートは後段のリミッタが受ける。
5. ゲイン適用（L/R 共通）。A = 0 dB（スムージング後も）なら計算しない。

### 3.3 先読みリミッタ（Soft Knee ＋ ブリックウォール）

天井 C = OUTPUT、しきい値 T = THRESHOLD（どちらも dB、20 ms でスムージング。T > C のときは T = C）。
先読み D = round(10 ms × fs)（固定）、アタック A = round(ATTACK × fs)（0〜D）。

1. 目標ゲイン（毎サンプル）: ピーク `p = max(|L|, |R|)` を dB にした x から、静特性（Soft Knee）で出力 y を求め、
   `g_t = 10^((y − x)/20)`。
   - x ≤ T: `y = x`（何もしない。比較 1 回で済ませる）
   - x > T: `y = T + G·(1 − e^(−(x−T)/G))`、G = C − T
     （T で傾き 1 から曲がり始め＝折れ目なし。C に漸近し、超えない）
   - G ≈ 0（T = C）: `y = C`（従来のブリックウォール）
   - 念のため `g_t ≤ C / p` も満たす（天井の 0.0001 dB 下）。
2. **最小値ホールド**: 時刻 t−D〜t−D+A の `g_t` の最小値（単調デック、O(1)）。
3. **リリース**: ゲインが戻る方向だけ 1 極（時定数 RELEASE）で追う。下がる方向は即座。
4. **箱型平滑**: 直近 A+1 サンプルの移動平均（長さ ATTACK の直線的な下降）。
   ホールドと平滑の窓を揃えているので、下降はちょうどピークの位置で終わり、ピークが出力に着く時点で必ず下がり切っている。
   ATTACK 0 ではピークのサンプルで即座にゲインが変わる。
5. 音声を D サンプル遅らせて（ディレイライン）ゲインを掛ける。ATTACK を変えてもレイテンシは変わらない。
6. **安全クリップ**: 最後に ±C でハードクリップ。平滑の丸め誤差（と、ATTACK を長くした直後の一瞬）を受けるだけで、
   通常は一度も効かない（テストで確認、§5）。

GR（dB）= `20·log10(g)`。表示・履歴用に列ごとの最大を記録する。

### 3.4 OUTPUT

OUTPUT は天井そのもの（Ozone の Output Level と同じ）。出力段で別にゲインは掛けない。
UPWARD のしきい値（−12 dBFS）は OUTPUT と独立。

### 3.5 レイテンシとバイパス

- Core に `MyFXKernel.latencySamples`（既定 0）を足し、`MyFXAudioUnit.latency` がそれを秒で返す（§4.1）。
  MyDAW はマスター・FX チャンネルのプラグインレイテンシを既に補正している
  （`AudioEngineManager.masterPluginLatency`、`updateLatencyCompensation`）。
- レイテンシは **バイパス中も変えない**: バイパス時も N サンプル遅らせた素通しを出す
  （ON/OFF で時間が飛ばない）。ON/OFF の切替は 10 ms のクロスフェード（MyChannelStrip と同じ）。
- サンプルレートが変わったら N を再計算（`prepare`）。
- MyDAW はトラックのインサートの遅延も補正しているので、マスター以外（バス・トラック）に挿しても時間はずれない。

### 3.6 エディタへの受け渡し（レンダースレッド → UI）

既存の `MyFXMeterPeaks` と同じ方式（ロックなし、32 bit 1 語ずつ）。

| 値 | 用途 |
|---|---|
| 入出力ピーク | IN / OUT メータ、CLIP ランプ（Core のまま、≥ 1.0 で CLIP） |
| GR 最大・ブースト平均（前回取得以降） | 読み値 `GR` / `UP` |
| 履歴の列（SPSC リングバッファ 1,200 列） | ヒストリ・グラフ |
| サンプルレート | 列の長さの計算 |

- 記録は最も細かい 3 s 表示に合わせ、1 列 = fs × 3 s / 284 サンプル（約 10.6 ms）。
  6 s / 12 s 表示では UI 側で 2 列 / 4 列を 1 点にまとめる（ピークと GR は最大、ブーストは平均）。
  まとめる組は列の通し番号で固定し（列 0〜1、2〜3…）、そろった組だけを表示する（描いた点が後から変わらない）。
- 描画: レベル・GR・UPWARD を各 1 枚の輪郭（多角形）で塗り、縦の辺をデバイスピクセルに揃える。
  スクロールは常に整数ピクセルで、継ぎ目や端の滲みがちらつかない。
- リングは 1,200 列（約 12.7 s 分、12 s 表示に足りる）。
- 1 列 = { 出力ピーク, 最大 GR, 平均ブースト, バイパス中か } の 4 値。
  書き込みはレンダースレッドの列の終わりで 1 回、書き込み位置はアトミックに進める。
- エディタは 30 Hz で新しい列だけを読み、表示用の配列に追加する。

## 5. テスト

- **天井を超えない**: OUTPUT −0.1 / −1 / −6 dB、INPUT GAIN +24 dB で、
  サイン（20 Hz〜18 kHz）・インパルス列・ホワイトノイズ・矩形波を通し、全サンプルが天井以下。
  安全クリップが **一度も効かない**（効いた回数をテスト用に数える）。
- 天井より小さい信号（−20 dBFS サイン、UPWARD 0）: GR 0 で、出力 = 入力を D サンプル遅らせたもの（ビット一致）。
- レイテンシ: `latency` = D / fs（10 ms）、インパルスが D サンプル後に出る。バイパス中・ATTACK を変えても同じ遅れ。
- アタック: ATTACK 0 でピークの直前のサンプルは無変化・ピークで天井、ATTACK 5 ms でピークの 5 ms 前から下降。
  ATTACK 0 / 2 / 10 ms × RELEASE 10 / 50 / 500 ms で天井を超えない。演奏中に ATTACK を動かしても天井を超えない。
- リリース: RELEASE 10 / 50 / 500 ms で、その時定数で戻る（±10 %）。
- THRESHOLD（Soft Knee）: 静特性の値（§0 の表）、膝で傾き 1（折れ目なし）、単調増加で C 未満。
  0 dBFS のサインに THRESH −6 で約 −2.2 dBFS、THRESH より小さい信号はビット一致で素通し。
  THRESH −30 / −12 / −3 dB・INPUT +24 dB でも天井を超えない。THRESH ≥ OUTPUT はブリックウォールと一致。
- UPWARD: −30 dBFS のサインに約 +A dB、−12 dBFS 以上の信号で 0 dB、最初から無音（−80 dBFS）なら 0 dB。
  アタックはリミッタの ATTACK（0 ms で即座）、リリースはリミッタの RELEASE の 10 倍。
  無音の間はブーストを保持し、音が戻ると最初から持ち上がっている（不具合修正の確認）。UPWARD を下げると無音中でも追従。
  A = 0 で計算しない（出力ビット一致）。
- パラメータ変化（GAIN 0 → +12 dB 等）中に隣接サンプル差の上限（クリックなし）。
- 履歴: 列の長さ、リングの巻き戻り、6 s / 12 s のまとめ方、バイパス中の列。
- CLIP: 1.0 ちょうどで点灯、0.999 で点灯しない、クリックで消える（Core テスト）。
- モノラル（1 ch）、状態の保存・復元、アドレス・identifier の重複なし、サンプルレート 44.1 / 48 / 96 kHz。
- `MyPlugInSnapshots` でエディタ PNG を確認（グラフはテスト用の履歴を流し込んで描く）。
